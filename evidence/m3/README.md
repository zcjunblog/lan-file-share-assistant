## WorkBuddy短有效期发现

第一轮指定60秒，先start，再独立status，再另一次调用下载；工具间隔导致下载落在截止之后38秒，连接被拒绝、未取得文件，没有计为成功。第二轮保持60秒，将独立status与下载摘要核验合并到同一执行调用，页面和文件均返回200，源文件、下载文件、status报告三方SHA-256相同。

两次真实到期均已核验，第二次客户端复核发生于截止后约44.5秒，**不据此声称该客户端测得了亚秒级清理延迟**。亚秒级结果来自M2本机看门测试和M3受控进程恢复测试。默认10分钟未改，短有效期会消耗在ready之后的工具调用与回复中，不能静默续期。

WorkBuddy原始smoke-evidence.json、各调用JSON、已失效二维码副本及下载样本只在outputs/m3/workbuddy-smoke；本仓库使用白名单摘要。主Agent另行读取下载副本逐字节比较、计算SHA-256、核对实际终态、资源删除和端口关闭，不仅采用客户端文字结论。

实际运行的初始开发包基于M2提交7bb119e；M3故障修订另经48项回归验证。[更新记录](installed-update.json)核对：UI拒绝同名重复导入后，保留原包并原子同步这个唯一自有Skill，10份源码与仓库一致。更新后的完整WorkBuddy流程已在[补充验收](continuation.md)通过；正式发布包仍需M4构建和安装烟测。

## 复现与资料范围

```sh
.venv/bin/python -m unittest discover -s tests -v
```

以下会使用合成文件启动有限局域网服务，只在已授权的本机开发验收中运行。第一次独立工具调用：

```sh
.venv/bin/python tools/m3_lifecycle.py prepare
```

下一次独立调用，60秒内执行：

```sh
.venv/bin/python tools/m3_lifecycle.py exercise
```

exercise约60秒完成，应使用执行工具短时yield以保持沟通。只对它自行创建并认证的Popen子进程使用信号，绝不按端口或随意PID杀进程；异常退出测试确认进程结束后才显式清理本次私有目录。它不操作整机睡眠、系统时间、防火墙、路由或VPN。

WorkBuddy由真实本机客户端交互验收，开发ZIP不含运行状态/凭据；不是市场发布、审核或上线。手机反馈是用户报告与本地状态核验的组合；不从验收码反推机型、浏览器或完整字节摘要。
