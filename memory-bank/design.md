# 局域网文件分享助手 产品设计

更新日期：2026-11-06（Asia/Shanghai）。
当前阶段：按用户要求执行GitHub开源，改进正式README并采用MIT；WorkBuddy0.1.0已提交审核，审核通过与上线尚未确认。Windows/Linux实验性、整机睡眠暂缓及未验收边界保持。

## 1. 已确认需求与本轮范围

- 中文名称固定为“局域网文件分享助手”。
- 首版围绕指定文件、扫码下载、自动过期三项功能。
- 创建分享之前必须检测本地配置是否支持；不支持时说明具体原因。
- M0/M1/M2已完成；用户已要求继续M3，核验故障及设备/客户端并同步资料。用户配合手机扫码，明确本轮暂不整机睡眠。
- 延续既有生态的跨客户端方向，以标准Agent Skill为主体，按需提供WorkBuddy适配；不能承诺所有宿主都能运行本地网络服务。
- 项目标识采用lan-file-share-assistant。私有仓库已建立于https://github.com/zcjunblog/lan-file-share-assistant ，公开、许可证、收费和提审另行决定。

M0初稿中的技术提案由M1进一步收敛，[预检与会话协议](../docs/preflight-and-session-protocol.md)为当前冻结依据。参数属于工程选择，不写成用户逐项指定；协议及探针完成不等于生产功能已经实现。

## 2. 产品定位与价值

将用户选定的本地文件临时分享给同一可互通局域网内的手机或其他电脑，接收方通过二维码进入浏览器下载页。

优先解决Agent产物交付：需求确认书、图文操作手册、PDF、图片和资料包生成后，可以继续用自然语言要求分享。文件生成与文件分享保持独立授权，只分享本次明确选择的内容。

适用人群包括办公人员、项目交付人员、培训团队和需要跨设备取文件的个人。首版不建设长期文件中心，不维护账号、团队权限或长期存储。

## 3. 首版输入与输出

### 输入

- 一个或多个明确指定的本机普通文件，或用户明确授权的上一任务产物清单。
- 分享标题、有效期，可选指定网卡/局域网地址；缺少有效期时默认10分钟，并在启动前后明确显示。
- 用户目标：例如“把这份操作手册分享给手机，十分钟后关闭”。

文件夹、目录递归与动态新增文件不进入首版；用户可自行提供ZIP。M1冻结每会话1至20个文件、单文件最多2GiB、总计最多5GiB、有效期1至60分钟。容量属于设计上限，尚未完成实际传输验收。大文件使用流式传输，不默认整文件载入内存。

### 输出

- 启动前的环境检查结论及逐项原因。
- 本机具备条件时：选定文件列表、总大小、局域网链接、可扫码二维码、准确截止时间和停止方法。
- 接收端页面：标题、文件名/大小、下载入口、有效期与失效状态；白蓝办公风格，移动端优先。
- 会话状态：运行中、已停止、已过期或启动失败，状态来自实际进程及截止时间，不由Agent猜测。
- 内部检查报告和会话元数据只保存在本机，不默认交给接收方或上传仓库。

## 4. 分享前本地配置检测

预检是强制入口，未满足关键条件时不创建文件分享、不显示“可用”二维码。初始化阶段不执行这些网络探测；在后续实际分享任务中，先进行无文件暴露的必要检查。

| 检查项 | 要确认的能力 | 失败或无法确定时的处理 |
| --- | --- | --- |
| 宿主位置 | 程序运行于拥有待分享文件的本机，能接触该电脑的局域网 | 仅云端/沙箱地址不算本机支持；说明需要本地运行环境 |
| 程序执行 | 存在受支持运行时，允许执行本项目脚本 | 说明缺少运行时或执行权限；给出本地安装/切换环境步骤，不自动改全局环境 |
| 文件范围 | 指定文件存在、可读，物理路径与授权范围明确 | 逐项说明缺失、拒绝访问、目录输入或路径问题；不能自动扩大范围 |
| 工作目录 | 可创建独立状态目录和二维码文件，且不覆盖源文件 | 提示选择可写位置；不回退写入其他敏感目录 |
| 二维码能力 | 有本地可运行的二维码生成器，能编码实际分享地址 | 明确缺少能力及修复步骤；不能只给链接却声称扫码功能完成 |
| 局域网地址 | 存在合适的本机IPv4私有地址，能确定待使用接口 | 仅回环、虚拟网卡或多候选无法确定时解释并让用户选择，不凭空生成IP |
| 端口与本地权限 | 所选地址上的端口可绑定，没有被占用或策略拒绝 | 尝试有限数量的可用非特权端口；仍失败就说明原因，不结束其他应用 |
| 进程生命周期 | 宿主能维持服务进程，并能在到期或手动停止时关闭它 | 宿主会结束后台进程或缺少控制能力时说明不支持当前分享方式 |
| 启动后自检 | 服务启动后，健康接口及选定文件的授权访问检查通过 | 启动失败立即回收本次进程；不发布失效链接 |
| 接收端连通性 | 另一设备能实际访问本机服务 | 独立标记未验证/已验证；本机自测不能替代手机扫码 |

逐项状态拟采用pass、fail、unknown。整体结论分为：

- supported：本机关键启动条件已满足，可继续创建；接收端可达性仍单列。
- needs_action：用户可修复的依赖、权限、网卡选择或端口问题；列明下一步与复检方法，暂不创建。
- unsupported：当前运行位置或宿主不具备本地服务能力；说明不能支持的功能和可行的本地运行替代方式。

关键能力未知也不能按通过处理。防火墙、访客Wi-Fi/AP隔离、路由策略和手机局域网权限未必能从本机可靠判定；如无法检测，明确写“未验证”，不谎称全通过，也不把它等同于宿主一定不支持。

### 不支持时的反馈格式

至少包含：结论、失败检查项、实际原因、影响、可执行的处理步骤、处理后如何重新检测。

示例：“当前任务运行在云端容器，无法使用你电脑的局域网地址，所以暂不能创建手机扫码下载。请在拥有这些文件、可运行本地程序的Agent客户端中执行；切换后重新检查运行时、地址与端口。”这是反馈文案示意，不是当前设备检测结果。

## 5. 用户流程

1. 明确本次分享的文件范围和有效期，核对是否包含不应外发的工作资料。
2. 运行环境预检，展示可理解的检查结论；关键条件不满足时说明并停止。
3. 固定文件白名单与会话配置，选定地址和端口，生成不可预测的临时访问凭据。
4. 启动有到期控制的本地服务，进行健康和访问自检；失败时清理本次资源。
5. 仅在自检成功后展示真实链接、二维码、文件清单与截止时间；明确接收端尚未验证。
6. 手机或另一台电脑扫码，浏览器下载选定文件；记录实际访问和传输状态。
7. 到期自动停止，或用户提前要求停止；核实本项目监听已关闭，访问凭据失效，保留原文件。
8. 如需再次分享，重新预检并创建新会话，不复用已经过期的凭据。

首版只支持下载，不支持接收方上传、修改、删除文件或执行文件内容。

## 6. 技术方案提案

采用“Agent编排 + 确定性本地服务 + 本地二维码生成”的结构。Agent负责理解分享范围、解释检查报告和展示结果；本地程序负责文件读取、HTTP响应、会话控制与强制过期。

M1选择Python3.9+与标准库作为服务核心目标，二维码使用Segno1.6.6，本地生成PNG/SVG且无Pillow运行必需项。M1验证环境为宿主Python3.12.14的项目虚拟环境，协议校验/独立解码采用jsonschema、zxing-cpp和Pillow开发依赖；它们不成为Skill运行必需项。依赖缺失不自动修改全局Python，不依赖外部模型API或云端二维码服务。

首版拟使用可信局域网中的HTTP下载，随机凭据用于限制访问，不提供传输加密。明确显示这一边界，不能宣传端到端加密、公共Wi-Fi安全或完全保密；需要加密的使用场景应另行采用适合的方案。HTTPS及证书体验不作为首版既定能力。

拟只绑定用户选定的IPv4私有地址，不绑定0.0.0.0、IPv6公网地址或所有网卡。不添加路由器映射、公网隧道、STUN/TURN或自动设备发现；同一Wi-Fi名称不保证设备可以互通。

下载URL通过不透明文件ID映射会话白名单，不能把URL路径拼接为任意本地文件路径。文件名做HTML与响应头安全处理，下载响应采用附件方式，避免把用户文件当网页执行。源文件需防替换、符号链接与路径越界，具体快照/打开文件策略在M1落实。

本机网络检查与下载服务均应有限时、有限重试、可停止；不自动关闭防火墙、申请管理员权限或终止其他服务以求“检测通过”。

## 7. 自动过期与状态一致性

- 启动时固化截止时间，由服务程序独立执行，不依赖Agent后续发消息或外部定时任务。
- 每次访问和流式传输期间均检查是否到期；首版拟到期拒绝新请求并终止仍在进行的传输，界面提前说明此策略。
- 墙钟截止时间与经过平台核对、包含系统休眠的连续单调计时配合，避免时钟回拨延长有效期；后端不明不放行，睡眠恢复后先校验是否过期。
- 浏览器刷新、再次扫码、下载失败或页面倒计时不能自动续期；延期应创建新会话或遵循后续明确设计。
- 到期停止监听、撤销凭据并清理本次敏感会话信息；不能只让前端按钮变灰。
- 停止前校验进程归属，不能仅凭PID或端口号杀进程。进程已被宿主结束时如实报告停止，不把旧状态文件当作正在分享。
- 已经下载到接收端的文件副本无法通过过期撤回；源文件不删除、不修改。

## 8. 资料与安全边界

只暴露用户明确授权的文件，不开放整目录浏览或默认共享桌面/工作区。只支持普通文件，不读取设备文件、管道、目录或未授权的符号链接目标。

二维码在本地生成，不调用第三方二维码API。访问凭据和完整分享链接只在本机会话与用户交互中显示，日志及错误信息应隐藏凭据；本机IP、绝对路径、分享文件与运行状态不提交GitHub。

新会话使用新凭据；未授权、非法或已过期请求不能取得文件。服务状态、网页和日志需一致，不能把“某次请求返回成功”直接说成接收方已保存完整文件；测试时以实际接收文件摘要验证完整性。

## 9. 失败处理

| 情况 | 产品反馈 |
| --- | --- |
| 依赖缺失或宿主不允许执行 | 清楚说明当前不能创建及本地修复/切换方式 |
| 多网卡、VPN地址或无法找到合适地址 | 展示必要候选与用途，待用户选择后复检，不修改VPN设置 |
| 端口占用或网络权限拒绝 | 有限重试其他端口，失败后报告具体检查结果 |
| 本机自检通过但手机打不开 | 区分网络不互通与程序未启动，提示核对实际网络、防火墙和设备隔离；不声称已诊断出未观察到的原因 |
| 文件被修改、删除或替换 | 阻止提供未经核对的新内容，报告对应文件；不自动追踪到其他目录 |
| 已过期或已手动停止 | 明确说明分享失效，重新分享需创建新会话 |
| 宿主退出、设备睡眠或服务中断 | 如实说明服务状态和可能的连接中断，不承诺后台永久可用 |

## 10. 验证与完成标准

1. 不支持环境可复现地返回原因及修复步骤；在通过关键预检前不开放文件下载。
2. 用合成文本、中文文件名、PDF与ZIP验证白名单分享，下载字节摘要与指定原文件一致。
3. 非白名单路径、路径穿越、非法凭据、符号链接和来源替换不能读取未授权文件。
4. 用真实同网手机扫码完成下载，并将此证据与本机健康检查分开记录；不能仅在电脑上打开二维码链接就宣称手机可用。
5. 验证手动停止、正常过期、过期中的下载、时钟变化、睡眠恢复与宿主结束；到期后监听和访问行为符合实际设计。
6. 网卡不明确、端口冲突、权限拒绝、二维码能力缺失与对端连接失败有清晰反馈，不绕过检测。
7. 页面与二维码在手机上可读，中文长文件名和下载状态不溢出。
8. 标准Skill包与WorkBuddy包共享业务源码；真实宿主能力单独实测，不能把目录安装适配写成全客户端支持。
9. 发布资料与包内不含真实分享文件、访问凭据、本机地址或开发机私有路径。

M2已完成生产源码与本机实际HTTP链路；手机、目标客户端、真实睡眠/时钟变更等仍待M3验收。M1探针、M2本机服务、实际跨设备证据分别记录。

## 13. M1工程结论与证据

- 冻结请求/预检JSON结构、8项关键检查、supported/needs_action/unsupported汇总规则、30秒预检时效与can_publish=false边界；缺项、未知或无依据的关键项不能放行。
- 冻结私有快照、显式RFC1918地址、随机访问/控制凭据分离、状态机、到期中断与本地控制方式。未监听bind不预留端口，正式启动重新绑定并自检。
- 当前macOS中系统Python3.9.6和宿主Python3.12.14可执行。系统环境缺二维码库；项目虚拟环境准备Segno后，合成PNG/SVG生成及zxing-cpp独立回读通过。
- 本机发现1个活动物理接口候选；两解释器各执行回环与候选地址bind后关闭，共4次，4次占用冲突均被拒绝。没有调用listen/accept或启动HTTP服务。
- 合成文件读写、普通文件识别、打开描述符后原路径被替换的身份差异、符号链接识别通过；这些是OS原语验证，不是完整安全文件服务。
- 无网络子进程在两次工具调用间出现新心跳，约12.091秒自行结束且已确认不再运行；不能据此保证聊天结束后或WorkBuddy中的长期运行。
- 本机mach_continuous_time原生API存在且短等待后正向推进；包含休眠的性质依据Apple文档，并未实际使电脑睡眠或修改系统时钟。到期后端未知时阻止放行，不能默认time.monotonic在每个平台都包含休眠。
- 12项协议测试包含35组合成请求/报告/时间边界案例，并覆盖篡改结论、缺失/重复检查、未知依据及过时报告。
- 原始本机IP、端口、路径和进程归属详情仅在忽略目录outputs/m1；仓库证据采用白名单脱敏摘要，见[evidence/m1](../evidence/m1/README.md)。

真实手机、Windows/Linux、云端/容器/沙箱、完整服务存活、睡眠与实际到期关闭仍未实测。下一阶段为M2生产预检与分享服务实现，不自动跨入M3或市场提交。


## 14. M2实现与当前验收边界
